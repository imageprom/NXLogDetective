# NX Log Detective (NXLD) 0.2.3

Скилл для Claude, который разбирает access- и error-логи сайта (nginx, Apache) и выдаёт отчёт в Excel, текст для Redmine и пакет сигнатур STIX 2.1. Работает по ТЗ «NX Log Detective 1.0». Пока версии нумеруются 0.x: идут тестовые прогоны на реальных сайтах.

Принцип: **код измеряет, ИИ расследует**.
- **Движок** (`engine/`) считает всё, что можно посчитать, и собирает таблицы.
- **ИИ** (Детектив) проверяет карту сайта, расследует странное, правит ошибочные выводы и пишет связный текст для Redmine.

Состояния между проверками нет: всё нужное приходит на вход, всё полученное уходит на выход. Для повторной проверки на вход подаётся снимок прошлой.

## Установка и обновление

1. Скачайте `nx-log-detective-<версия>.zip` со страницы [релизов](https://github.com/imageprom/NXLogDetective/releases) или из папки [releases/](https://github.com/imageprom/NXLogDetective/tree/main/releases).
2. В Claude: Настройки → Скиллы → загрузить архив. Внутри одна папка `nx-log-detective/`: SKILL.md, references/, движок, базы, инструменты, этот README.
3. **Обновление:** удалите старый скилл в настройках и загрузите архив новой версии. В начале каждой проверки Детектив сам смотрит, нет ли версии новее (`tools/check_update.py`), и только сообщает об этом.

Собрать архив из репозитория: `python3 tools/build_skill.py` (кладёт в `releases/`) или `--out <папка>`.

## Как проходит проверка

1. **Анкета.** Какие блоки нужны, полная проверка или сравнение с прошлой, подозрительные IP, отметки «это норма».
2. **Приём и разведка** (`prepare`). Движок читает логи, определяет сайт, формат, сервер и движок сайта, цели, рекламные метки, сотрудников. Детектив показывает первый экран «Что на входе» и при необходимости поправляет карту сайта.
3. **Расчёт** (`analyze`). Движок считает листы, черновые проблемы и выжимку `work/brief.json`.
4. **Расследование.** Детектив проверяет срочные проблемы, разбирает незнакомые параметры, расширения и мониторинги, просит у человека адреса для проверки из сети. Всё найденное записывает в `edits.json`.
5. **Сборка** (`report --edits`). Движок собирает отчёт с правками и пересобирает выжимку.
6. **Текст для Redmine.** Детектив пишет его по выжимке в голосе из `skill/references/redmine.md`.

## Запуск движка

Нужны Python 3 (проверено на 3.11) и `pip install pandas numpy openpyxl`.

```bash
python3 engine/nxld_run.py --logs ./logs --work ./work --stage prepare
python3 engine/nxld_run.py --work ./work --stage analyze --blocks all
python3 engine/nxld_run.py --work ./work --out ./out --stage report --edits edits.json
```

Без `--stage` выполняются все три этапа подряд.

| Параметр | Что делает |
|---|---|
| `--logs` | Файлы и папки с логами: `.log`, `.gz`, `.zip`. Многотомные zip (`.z01`…) не читаются |
| `--work` | Рабочая папка с промежуточными таблицами (обязательно) |
| `--out` | Папка для результата |
| `--stage` | `prepare`, `analyze`, `report` или `all` |
| `--blocks` | `overview,errors,load,bots,marketing,seo` или `all`. Обзор и Ошибки строятся всегда |
| `--map-override` | Поправки карты сайта: `site_hosts`, `staff_ips`, `staff_ips_remove` |
| `--check-ips` | IP через запятую для отдельной проверки |
| `--prev` | Снимок прошлой проверки (`.snapshot.json`): сравнение «было → стало» |
| `--marks` | Отметки «это норма»: `{ключ_проблемы: комментарий}` |
| `--edits` | Правки Детектива: проблемы, дела, IP людей, справочники, проверки из сети |
| `--redmine` | Текст для Redmine, если он лежит не в `work/NXLD_Redmine.textile` |
| `--only` | Собрать только указанные файлы отчёта |
| `--skip-existing` | Не пересобирать уже собранные файлы отчёта (после падения на середине) |
| `--site` | Имя сайта, если его не удалось определить по логам |

Ресурсы: на 7 млн строк `prepare` идёт около 6 минут, расчёт около получаса, сборка около часа. Нужно больше 8 ГБ памяти.

## Что получается на выходе

| Файл | Для кого и о чём |
|---|---|
| `NXLD_01_Overview.xlsx` | Для всех. Обзор проверки, все проблемы, устройство сайта, активность, конверсии, страницы, файлы, параметры, логи |
| `NXLD_02_Errors.xlsx` | Ошибки: коды ответа, сбои и торможение, битые ссылки, мягкие ошибки, error-лог |
| `NXLD_03_Load_Security.xlsx` | Нагрузка и безопасность: пики, источники нагрузки, серверный фильтр, сканеры, атаки, служебные данные |
| `NXLD_04_Bots.xlsx` | Боты: дела, сигнатуры, меры по IP, операторы, спам форм, подделки, роботы |
| `NXLD_05_Marketing.xlsx` | Маркетинг: каналы, воронки, аудитория, реклама, кампании, площадки |
| `NXLD_06_SEO.xlsx` | SEO: обход поисковиками, файлы для роботов, паразитные адреса, поисковые ошибки, органика, ИИ-видимость |
| `NXLD_0n_<файл>_<лист>.csv` | Полные списки больших листов (больше 10 000 строк). В Excel тогда первые 1 000 строк и ссылка на CSV. Карточки дел не обрезаются |
| `NXLD_<сайт>_<с>_<по>.stix.json` | Пакет STIX 2.1: сигнатуры (правило Sigma и шаблон STIX), дела, адреса, связи |
| `NXLD_Redmine.textile` | Текст для Redmine. Если Детектив его не написал, движок кладёт `NXLD_Redmine_черновик.textile` |
| `NXLD_<сайт>_<с>_<по>.snapshot.json` | Снимок для следующего сравнения |
| `NXLD_<сайт>_<с>_<по>.zip` | Всё вместе |

В каждом файле первым листом идёт Обзор, вторым — Проблемы своего блока. Состав, порядок, статусы, вкладки и заголовки листов заданы в каталоге структуры `data/locale/ru/report_structure.json`: выводятся только листы `approved`, листы `review` — только с `NXLD_SHOW_REVIEW=1` (модельные прогоны для согласования).

**Персональные данные и секреты.** Телефоны и почты в отчётах маскируются по значению, а не по имени параметра. Рекламные и поисковые идентификаторы (clid, yclid, gclid и т. п.) не маскируются. Значения секретов в адресах (sessid, token, USER_CHECKWORD, password…) обрезаются до первых 4 символов. IP злоумышленников показываются полностью. IP, которые Детектив признал адресами людей, убираются из дел, мер по IP и STIX.

## Что нового

**0.2.3**
- «Люди» точнее: визит из одних файлов без страниц (хотлинк, скрапер картинок) и сканер со «статикой», которую не подгружала страница визита, — не люди; на сводке 01 — доля людей из страны основной аудитории.
- Страница входа движка (/auth/ на Битриксе) и страницы, которые отдаются людям, — не зонды: нет ложной «Разведки» в делах.
- «@» во внешней ссылке goto= — не персональные данные; новая карточка «Открытый редирект».
- «Свои» — по входу и работе в админке, а не по форме входа, которую сервер отдаёт любому.
- IP с обычными визитами людей не попадают в STIX и в «Меры по IP» с блокировкой; в «Составе дел» — пометка.

**0.2.2**
- Маскировка персональных данных по значению; рекламные и поисковые идентификаторы не маскируются; секреты в адресах обрезаются.
- Лист «Серверный фильтр» в 03: кому защита сервера отказывает — поисковым роботам, роботам проверки объявлений, людям.
- Лист «Мягкие ошибки» в 02: одна и та же страница на множестве адресов, адреса без косой черты, «не найдено» с кодом 200.
- Большие листы — в CSV рядом с Excel.
- Проверка каталога листов: лист, которого нет в каталоге, даёт предупреждение.
- Пустые данные (нет людей из рекламы, нет параметров запросов) больше не роняют сборку.

**0.2.1**
- Формат лога с именем хоста после `$remote_user` и с BOM в начале файла.
- Остановка с понятным сообщением, если access-лог не распознан.
- `staff_ips_remove` в поправках карты, `--skip-existing` при сборке.
- Правки `edits.json`: «дела» (оправдано, важность) и «люди_ip».
- `analyze` больше не собирает отчёт, STIX строится один раз, выжимка пересобирается после правок.

## Что дальше

По приоритетам:
1. **Быстрые и точные отчёты.**
   - Новая структура файлов. 01 Обзор становится легче: краткие карточки стека и хостов, «Карта сайта» деревом. Новый файл 02 «Архитектура»: устройство сайта, паспорт системы, хосты, во что обходится каждый тип страниц, скорость, сбои, error-лог, кэш, холостая нагрузка. Остальные файлы сдвигаются на номер.
   - Уровень данных 0.3: логи читаются потоком в одну базу DuckDB, все листы, CSV, STIX и снимок собираются из неё. Цель — 7 млн строк за 15 минут и до 4 ГБ памяти.
2. **Сравнение «было → стало»** на уровне данных.
3. **Экспорт и импорт:** правила защиты для nginx, fail2ban, WAF; Sigma и EQL отдельно; мировые базы ботов и вредных адресов.

Позже: «Показания свидетелей» — диалог с человеком, где его ответы сверяются с логом; версия для ChatGPT.

## Состав репозитория

| Папка | Что |
|---|---|
| `engine/nxld_run.py` | Запуск этапов prepare → analyze → report |
| `engine/nxld/` | Модули движка. Каталог структуры отчёта — `catalog.py` (читает `data/locale/<язык>/report_structure.json`), коды листов и старые имена для ссылок — `sheets.py` |
| `engine/tests/` | Тесты на синтетических логах |
| `data/` | Базы: IP → сеть и страна, официальные сети роботов, справочники параметров, расширений, мониторингов, регионов (`data/reference/README.md`); логотип для отчётов |
| `skill/SKILL.md` | Инструкция для Детектива |
| `skill/references/` | Как писать текст для Redmine, образцы тона (обезличены) |
| `tools/` | Сборка архива скилла, проверка обновлений, обновление справочников |
| `releases/` | Архивы скилла по версиям |
| `signatures/legacy/` | Старый ручной формат botsig/1, только для справки |

## Для разработки

```bash
cd engine && NXLD_STRICT_CATALOG=1 python3 -m pytest -q tests
git checkout -- data/reference/learned   # прогоны дописывают справочник — перед коммитом вернуть
```

С `NXLD_STRICT_CATALOG=1` лист вне каталога структуры считается ошибкой. Логи клиентов в репозиторий не кладутся: репозиторий публичный.
