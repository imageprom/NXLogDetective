# NX Log Detective (NXLD) 0.2.0-alpha

Скил NX Log Detective анализирует access- и error-логи сайта (nginx, Apache) по ТЗ «NX Log Detective 1.0». Сборки до прохождения тестовых прогонов нумеруются 0.x.

Принцип: **код измеряет, ИИ расследует**.
- **Движок** считает всё, что можно посчитать, и собирает таблицы.
- **ИИ** проверяет карту сайта, расследует странное и пишет связный текст для Redmine от лица Детектива.

Сейчас ИИ — это Claude, позже добавится ChatGPT. Состояния между проверками нет: всё нужное приходит на вход, всё полученное уходит на выход.

## Установка и обновление скилла

1. Скачайте `nx-log-detective-<версия>.zip` из последнего [релиза](https://github.com/imageprom/NXLogDetective/releases).
2. В Claude: настройки → скиллы → загрузить архив. Внутри одна папка `nx-log-detective/`: SKILL.md, references/, движок, базы и инструменты.
3. Обновление — так же: новый архив из релиза загружается вместо старого. В начале работы Детектив сам проверяет, нет ли версии новее (`tools/check_update.py`), и только сообщает об этом.

Собрать архив из репозитория: `python3 tools/build_skill.py --out dist`. ТЗ — `docs/TZ_NXLD_1.0.md` (выгрузка из Claude Docs).

## Состав

| Папка | Что |

| `engine/nxld_run.py` | Запуск: prepare → analyze → report |

## Быстрый старт

```bash
pip install pandas numpy openpyxl
python3 engine/nxld_run.py --logs ./logs --work ./work --out ./out
```

Параметры:
- `--blocks overview,errors,load,bots,marketing` — блоки проверки; overview и errors считаются всегда;
- `--check-ips` — список IP для проверки;
- `--prev прошлый.snapshot.json` — повторная проверка, сравнение со снимком;
- `--marks` — отметки «это норма»;
- `--edits edits.json` — правки проблем после расследования;
- `--map-override map.json` — поправки карты сайта;
- `--redmine` — текст ИИ для Redmine;
- `--stage prepare|analyze|report` — выполнить один этап.

Порядок работы:
1. `prepare` разбирает логи.
2. `analyze` считает блоки и пишет выжимку `work/brief.json`.
3. ИИ расследует и пишет `work/NXLD_Redmine.textile`.
4. `report` собирает Excel по блокам, текст, снимок и архив `NXLD_<сайт>_<с>_<по>.zip`.

## Что есть в 0.2

- **Приём логов:**
  - `.log`, `.gz`, `.zip` и папки;
  - автоопределение access или error, сайта и формата;
  - дубли на стыках файлов удаляются.
- **Разведка:**
  - сервер и PHP-FPM; движок или «статический HTML»;
  - шаблоны адресов, элементы каталога;
  - цели и признак успеха, подгружаемые блоки;
  - рекламные метки, служебные файлы, сотрудники, мониторинги.
- **Очистка визитов:** двойные загрузки, редиректы, подгружаемые формы и блоки. Трафик делится на группы: люди, роботы, боты, свои.
- **Спам форм:**
  - поведенческие признаки;
  - отдельно учтена смена IP у человека (мобильная сеть, прокси браузера);
  - связывание адресов в операторов по уликам трёх сил с листом доказательств «Операторы: улики».
- **Ошибки:**
  - сбой показывается как пик и окно деградации вокруг него;
  - 5xx по шаблонам и разделам;
  - битые входы (в том числе адреса без косой черты в конце), фиды, отсутствующие файлы, error-лог.
- **Безопасность:** сканеры; что отдано и кому — своим или чужим; открытые служебные разделы; админка.
- **Маркетинг:** каналы, воронки, разрезы конверсии, типы рекламных площадок, кампании и площадки без заявок, метки.
- **Важность проблем** ставится по вреду. Мелкое уходит в «К сведению», однотипное сводится в одну проблему, давние сбои понижаются.
- **Текст для Redmine** пишет ИИ по `brief.json` и правилам из `skill/references/redmine.md`. Если текста нет, движок кладёт черновик с пометкой «Черновик».
- **Прочее:** Excel по блокам, снимок, сравнение со снимком прошлой проверки, отметки «это норма», правки ИИ.

## Чего пока нет (по ТЗ, следующие версии)

**Отчёты:**
- фирменное оформление;
- новая структура NXLD_01_Overview;
- понятные названия колонок;
- говорящие заголовки листов;
- прозрачные проблемы.

**Сигнатуры и экспорт (ТЗ, раздел 10).** Паттерны **строятся** из данных проекта: гипотезы → признаки → пороги → проверка на логах. Выгрузка бывает двух видов.

- **Экспорт и импорт — полный пакет STIX 2.1** без потерь, только стандартные объекты:
  - индикаторы с шаблонами `sigma` и `stix`;
  - адреса и сети;
  - связи, наблюдения, группы;
  - статусы: чёрный список, кандидат, анонимайзер, белый список, отклонён, истёк;
  - маркировка TLP 2.0.
- **Экспорт правил — частичный и в одну сторону:**
  - сигнатуры: Sigma 2.1.0 (YAML и JSON, с правилами корреляции), EQL;
  - правила защиты: nginx, fail2ban, ModSecurity/Coraza, Yandex Smart Web Security, AWS WAF, Cloudflare;
  - индикаторы: текстовый список IP, CSV.

Чужие файлы в частичных форматах — это проверка логов по чужим правилам, а не импорт.

**Мировые базы ботов и вредных адресов** — снимки в `data/` с автообновлением, только источники без ключей и регистрации:
- официальные списки адресов поисковых роботов;
- MISP warninglists;
- Spamhaus DROP, FireHOL, blocklist.de, IPsum;
- выходные узлы Tor;
- списки ботов по User-Agent;
- SigmaHQ, OWASP CRS и др.

**Прочее:**
- склейка визитов при смене IP для статистики людей (для спама форм уже есть);
- вариант для ChatGPT с работой кусками и продолжением после обрыва.

## signatures/legacy

`botsig/1` — формат ручного разбора, который был до ТЗ. Он оставлен для справки и ручной проверки. Новые сигнатуры и правила будут в форматах из ТЗ (STIX 2.1, Sigma, EQL, правила защиты), а не в botsig.
