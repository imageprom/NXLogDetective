# Справочники NX Log Detective

Это знания, которые не нужно каждый раз угадывать по логу: как устроены движки, какие метки ставят внешние сервисы и как сделаны типовые решения студии. Движок применяет записи только для того, что нашёл на сайте. Например, записи Битрикса работают только на сайте на Битриксе.

Порядок решения для любого адреса или параметра:

1. **Кто спрашивает.** Если запросы почти все от сканеров или значения похожи на атаку, это «Атаки и зонды», и справочник не нужен.
2. **Справочник.** Сначала решения студии, потом движок сайта, потом внешние сервисы, потом общий файл.
3. **Поведение** — для того, чего нет в справочнике: куда идут запросы, на страницы или во вставки, приходят ли ключи пачкой.
4. **Имя ключа** — в последнюю очередь.

## Папки

| Папка | Что там | Когда применяется |
|---|---|---|
| `common.json` | общее для всех сайтов: рекламные метки, метки поисковиков, сброс кэша, файлы для роботов | всегда |
| `engines/` | один файл на движок | только если движок определился на сайте |
| `services/` | внешние сервисы: коллтрекинг, метрики, рекламные виджеты, CRM | если на сайте нашлись их признаки или параметры |
| `solutions/` | самописные решения студии, которые повторяются от сайта к сайту | если нашлись их признаки |

Новый движок, сервис или решение добавляется новым файлом, код менять не нужно. Шаблон записи — `solutions/_template.json`. Файлы, чьё имя начинается с `_`, движок не читает: это шаблоны и черновики.

## Формат файла

```json
{
  "id": "bitrix",
  "название": "1С-Битрикс",
  "вид": "движок",
  "описание": "одна строка: что это",
  "заполнено": "полностью | частично",
  "источники": ["адрес документации"],
  "признаки": ["^/bitrix/", "^/upload/iblock/"],
  "папки": [{"путь": "/bitrix/", "роль": "система", "что": "ядро движка и служебные скрипты"}],
  "зоны": [{"путь": "/bitrix/admin/", "роль": "админка", "что": "панель управления"}],
  "адреса": [{"шаблон": "/filter/.+/apply/", "роль": "фасеты", "что": "страницы умного фильтра"}],
  "параметры": [{"ключ": "PAGEN_*", "группа": "Поиск и навигация", "что": "номер страницы списка"}]
}
```

**Поля:**

- `признаки` — регулярные выражения по пути запроса, по которым движок или решение узнаётся в логе. Хватает одного совпадения на заметном числе запросов.
- `папки.роль`:
  - `система` — ядро и служебные скрипты;
  - `шаблоны` — оформление и доработки сайта;
  - `загрузки` — файлы, которые загрузили на сайт;
  - `админка`;
  - `api`.
- `зоны.роль`: `админка`, `вход`, `кабинет`, `api`, `обмен` (1С, CRM), `служебное`.
- `адреса.роль`: `фасеты`, `поиск`, `корзина`, `оформление заказа`, `служебное`, `api`, `обмен`.
- `параметры.ключ`:
  - имя параметра без учёта регистра;
  - `*` — любое продолжение: `PAGEN_*` подходит для `PAGEN_1` и `PAGEN_2`;
  - ключи одного семейства на листе сворачиваются в одну строку.
- `параметры.группа` — одна из групп листа «Параметры запросов»:
  - `Реклама и аналитика`;
  - `Служебные поисковиков и Яндекса`;
  - `Данные форм`;
  - `Поиск и навигация`;
  - `Служебные движка`;
  - `Метки сервисов`;
  - `Сброс кэша`.
- `параметры.что` — короткое пояснение, его увидит аналитик.

**Необязательные поля любой записи:**

- `"источник": "документация"` или `"наблюдение"`. Без поля считается документацией.
- `"где_видели": "example.com, 2026-10"` — для наблюдений: на каком сайте и когда нашли.
- `"заметка": "…"` — оговорка для аналитика.

Если наблюдение подтвердилось на нескольких сайтах или в документации, пометку можно поменять на «документация».
