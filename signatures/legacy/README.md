# botsig/1 — машиночитаемые сигнатуры ботов для nginx access-логов

Набор из трёх файлов:

| Файл | Что это |
|---|---|
| `signatures.yaml` | Сами сигнатуры и справочные списки (IOC). Это то, что правится руками. |
| `botsig.schema.json` | JSON Schema формата — проверка, что файл сигнатур написан правильно. |
| `sigscan.py` + `uafam.py` | Движок: прогоняет логи через сигнатуры, выдаёт срабатывания. |

## Запуск

```bash
pip install pyyaml            # jsonschema — только для проверки формата
python3 sigscan.py --sig signatures.yaml --asn asn-ipv4.csv --out hits/ access.log.2.gz access.log.1 access.log
```

* Логи — в хронологическом порядке, `.gz` читается напрямую, `-` — stdin.
* `--asn` — база IP→ASN в CSV (`first_ip,last_ip,asn,org`), например пакет `@ip-location-db/asn` (файл `asn-ipv4.csv`). Без неё не работают проверки по сети (`asn`, `asn_verified`).
* Формат лога — стандартный nginx `combined`.

Результат:

* `hits/hits.jsonl` — по строке на срабатывание: сигнатура, IP, сеть, UA, время начала/конца, метрики и до 12 строк-доказательств.
* `hits/summary.csv` — сколько раз сработала каждая сигнатура и на скольких IP.
* `hits/ips.csv` — по каждому IP: максимальная серьёзность, список сигнатур и рекомендованные действия.

## Устройство сигнатуры

```yaml
- id: BS-SPAM-001                 # уникальный код
  title: "…"                      # человеческое название
  version: 1
  status: active                  # active | experimental | disabled
  category: form_spam             # form_spam | scraper | vuln_scan | fake_crawler | recon | click_fraud | headless | crawler_policy
  severity: critical              # info | low | medium | high | critical
  confidence: high                # low | medium | high — насколько сигнатура уверена, что это бот
  action: [reject_lead, block_ip] # monitor | flag | reject_lead | rate_limit | challenge | block_ip | block_subnet
  scope: session                  # request | session | window
  key: ip                         # ip | ip_ua — по чему группировать
  window: day                     # только для scope: window — day | hour
  where: {…}                      # фильтр: какие запросы вообще учитывать
  match: {…}                      # только для scope: request — условие на один запрос
  sequence: [ … ]                 # последовательность шагов (поведение)
  require: [ … ]                  # счётчики (поведение)
  description / false_positives / evidence / first_seen / last_seen   # документация
```

### Три уровня (scope)

| scope | Что проверяется | Пример |
|---|---|---|
| `request` | Один запрос | UA «Googlebot», а сеть не Google |
| `session` | Визит: запросы одного IP с паузами не больше 30 мин | «битый URL → главная → форма» |
| `window` | Все запросы ключа за час или сутки | 3+ разных UA при отправке форм за сутки |

### Условие на запрос (predicate)

Поля перечисляются через И. Значение поля:

* скаляр — равенство: `method: POST`, `status: 404`, `referer: "-"`;
* список — одно из: `status: [404, 410]`;
* оператор: `{re: …}`, `{not_re: …}`, `{in: […]}`, `{not_in: […]}`, `{in_list: имя}`, `{not_in_list: имя}`, `{cidr: […]}`, `{gt|gte|lt|lte: число}`, `{ne: …}`, `{exists: true}`.

Комбинации: `{any: [условие, условие]}`, `{all: […]}`, `{not: условие}`.

### Поля запроса

| Поле | Что это |
|---|---|
| `ip`, `asn`, `org` | Адрес, номер и владелец сети |
| `method`, `path`, `base`, `query`, `status`, `bytes` | Метод, полный адрес, адрес без параметров, параметры, код ответа, размер |
| `referer`, `ref_internal`, `ref_path` | Реферер; пришёл ли со страницы сайта; путь этой страницы |
| `ua`, `ua_family`, `ua_category`, `is_bot_ua` | UA; семейство и категория объявленного робота (`uafam.py`); объявляет ли себя роботом |
| `asn_verified` | Для роботов из списка `verified_crawlers`: true — сеть совпадает, false — подделка, null — не проверяется |
| `is_page`, `is_static`, `is_form_get`, `is_form_post`, `is_flat_card` | Тип запроса: страница, статика, загрузка формы, отправка формы, карточка объекта |
| `is_desktop`, `is_mobile`, `hour`, `day`, `yclid` | Тип устройства по UA, час и дата, номер рекламного клика |
| `ref_seen_404_other_ip` | Сколько секунд назад **другой IP** открыл страницу-реферер и получил 404 (иначе null) — признак смены IP посреди визита |

### Поведение: последовательность (sequence)

Шаги должны найтись в визите по порядку:

```yaml
sequence:
  - as: entry
    first_page_in_session: true      # это первая страница визита
    match: {method: GET, status: 404, referer: "-"}
  - as: home
    within: 900                      # не позже 15 мин после предыдущего шага
    match: {base: "/"}
  - as: submit
    within: 300
    max_pages_between: 4             # между шагами не больше 4 страниц
    match: {is_form_post: true}
```

### Поведение: счётчики (require)

```yaml
require:
  - {agg: count,    match: {is_page: true},   op: ">=", value: 1}   # сколько запросов
  - {agg: count,    match: {is_static: true}, op: "==", value: 0}   # «чего не было»
  - {agg: distinct, field: ua,                op: ">=", value: 3}   # сколько разных значений поля
  - {agg: burst,    match: {is_page: true}, window: 15, op: ">=", value: 6}  # максимум за любые 15 с
  - {agg: span,     match: {…},               op: "<=", value: 60}  # секунд от первого до последнего
```

Все условия `sequence` и `require` должны выполниться одновременно.

### Списки (lists)

Именованные списки в начале файла: IOC (адреса, URL) и справочники (`verified_crawlers`: семейство робота → разрешённые ASN). В условиях — `{in_list: имя}`. IOC-адреса домашних сетей быстро переходят к другим людям, поэтому сигнатуры по IP — только флаг, решение принимают поведенческие сигнатуры.

## Как добавить сигнатуру

1. Описать поведение словами и найти 2–3 примера в логах (они пойдут в `evidence`).
2. Записать в `signatures.yaml` со статусом `experimental`.
3. Проверить схему: `python3 -c "import yaml,json,jsonschema; jsonschema.validate(yaml.safe_load(open('signatures.yaml')), json.load(open('botsig.schema.json')))"`.
4. Прогнать по логам за 1–2 недели и посмотреть, не задевает ли людей (особенно тех, кто оставил реальные заявки).
5. Перевести в `active`.
