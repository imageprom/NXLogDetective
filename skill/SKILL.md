# NX Log Detective 0.1

Пиши бренд так: **NX Log Detective**, кратко **NXLD**. NX — всегда заглавными. В именах папок и файлов — без пробелов (`NXLogDetective`, `NXLD_…`).

Принцип: **код измеряет, ИИ расследует**. Всё, что можно посчитать, считает движок `engine/nxld_run.py`. Твоя работа — анкета, проверка карты сайта, расследование странного, формулировки проблем и выдача результата. Состояния между сессиями нет: всё нужное приходит на вход, всё полученное уходит на выход.

## 0. Подготовка

1. Движок лежит рядом с этим файлом: `../engine/` (или в распакованном архиве `NXLogDetective/engine/`). Нужны только Python 3, pandas, numpy, openpyxl. Интернет не нужен: база IP → сеть лежит в `../data/`.
2. Рабочая папка — любая (`./work`). Результат — `./out`.

## 1. Анкета (одним вопросом, ответ можно не ждать)

- **Блоки:** ☑ Общий анализ и ☑ Ошибки — всегда; ☐ Нагрузка и безопасность; ☐ Боты; ☐ Маркетинг.
- **Действие:** ◉ Полная проверка / ○ Сравнение (база: снимок `.snapshot.json`, старые логи или анализ в этом же чате).
- **Сигнатуры** (в 0.1 — черновик, см. раздел 6).
- **Дополнительно:** список подозрительных IP; контрольная точка («до и после»); отметки «это норма».

Если ответа нет — полная проверка по всем блокам.

## 2. Приём и разведка

```bash
python3 engine/nxld_run.py --logs <файлы и папки> --work ./work --stage prepare
```

Читает `.log`, `.gz`, `.zip`, папки; сам определяет access/error, сайт, формат, удаляет дубли на стыках файлов. На 10 млн строк — 2–3 минуты. Если файлы большие и передача рвётся — попроси части до 50 МБ.

Сразу покажи человеку первым экраном **«Что на входе»** из `work/inventory.json` и `work/site_map.json`:
- файлы и типы, сайты, период, число строк, пропуски, дубли;
- сервер (nginx/Apache, PHP-FPM), движок или «статический HTML», адрес админки;
- цели (формы) и признак успеха, элементы каталога, подгружаемые блоки, рекламные метки, сотрудники, мониторинги.

Проверь карту глазами. Если что-то не так (лишний домен, не та цель, свой IP) — запиши поправки в `map_override.json` (`site_hosts`, `staff_ips`, `catalog_templates`) и перезапусти prepare с `--map-override`. Неприменимое (нет форм, нет рекламы) не придумывай — так и пиши.

## 3. Расчёт блоков

```bash
python3 engine/nxld_run.py --work ./work --out ./out --stage analyze \
   --blocks overview,errors,load,bots,marketing \
   [--check-ips 1.2.3.4,5.6.7.8] [--control-point "2026-10-01 15:40"] \
   [--prev прошлый.snapshot.json] [--marks отметки.json]
```

Движок считает листы и черновые проблемы (`work/results.pkl`). Сравнение включается параметром `--prev`. Отметки «это норма» берутся из прошлого снимка автоматически.

## 4. Расследование (твоя часть)

Движок положил выжимку `work/brief.json`: проверка, портрет сайта, проблемы с важностью, материал по блокам, файлы и листы, открытые вопросы. **Начинай с неё, а не с таблиц.** Для точечных вопросов загрузи таблицы:

```python
import pandas as pd
R = pd.read_pickle('work/R.pkl')   # все запросы: ts, ip, method, base, query, status, bytes, ref, ua, fam, vid, is_page, tpl, goal ...
V = pd.read_pickle('work/V.pkl')   # визиты: group, subgroup, channel, entry, n_pages, n_static, n_goal, n_conv ...
```

Что делать:
- проверь каждую «Срочно»: правда ли это или артефакт (заглушка вместо файла, свой тест, мониторинг). Если первое подозрение не подтвердилось, это тоже вывод для текста;
- найди то, что правила не ловят: даты изменений, связи между IP, смысл листов «До и после», «Изменения статусов», «Операторы»;
- неопознанных роботов и мониторинги не угадывай: «не опознан — на усмотрение оптимизатора»;
- телефоны и почты в отчётах только маскированные;
- рамки: сначала «Срочно» и странное, до 10–15 уточняющих запросов, вывод команд короткий.

Правки проблем запиши в `edits.json` — они попадут в Excel:

```json
{"add": [{"блок": "Маркетинг", "важность": "Важно", "что_происходит": "…", "факты": "…", "где_править": "…", "что_сделать": "…", "главная_цифра": 0, "лист": "…"}],
 "remove": ["ключ ложной проблемы"],
 "update": {"ключ": {"важность": "К сведению", "факты": "…"}}}
```

## 5. Текст для Redmine (пишешь ты)

Прочитай `references/redmine.md`: голос Детектива, стиль, структура, проверка. При первом тексте в чате прочитай ещё один-два образца из `references/samples/`. Затем напиши связный текст по `brief.json` и своим находкам и сохрани его в `work/NXLD_Redmine.textile`.

Логи и Excel для текста не читай: всё нужное есть в brief. Если какого-то факта не хватает, добери его одним запросом.

## 6. Сборка результата

```bash
python3 engine/nxld_run.py --work ./work --out ./out --stage report --edits edits.json
```

Текст из `work/NXLD_Redmine.textile` попадёт в архив как есть. Если его нет, движок положит свой черновик с пометкой «Черновик».

На выходе (`./out`):
- `NXLD_01_Overview.xlsx` — «О данных», «Сводка», «Главное», карта сайта, общие данные, лист IP; скрытый лист со снимком;
- `NXLD_02_Errors.xlsx`, `NXLD_03_Load_Security.xlsx`, `NXLD_04_Bots.xlsx`, `NXLD_05_Marketing.xlsx` — первым листом «Проблемы» своего блока;
- `NXLD_Redmine.textile` — текст для Redmine;
- `NXLD_<сайт>_<с>_<по>.snapshot.json` — снимок для следующего сравнения;
- `NXLD_<сайт>_<с>_<по>.zip` — всё вместе.

## 7. Сигнатуры (0.1 — черновик)

Формат `NXLD-sig/2` зафиксирован в ТЗ как рабочий и будет дорабатываться. В 0.1 поведенческие признаки спама форм встроены в движок (`visits.mark_form_spam`), а прежний набор `botsig/1` лежит в `signatures/legacy/` для ручной проверки. Если пользователь прислал файлы сигнатур — скажи, что полноценная проверка по ним появится в следующей версии, и выполни её вручную по `R.pkl`, если это важно.

## 8. Интернет (только если есть и только по делу)

Всегда: robots.txt и заголовки главной (одним запросом). По поводу из лога: файлы sitemap, проблемный фид, перепроверка адресов из «Срочно» (до 10–20). Всё перечисли в «О данных». Без интернета — пометка «не проверено».
